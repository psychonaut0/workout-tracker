# Live Loop Stability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nothing in the live workout moves or disappears unless the user's own tap caused it.

**Architecture:** Three independent fixes:
- The ruler's tape is clipped to its own box.
- The controller stops closing the RIR strip on a timer, and gains three pieces of in-memory state: `restEndedAt`, `hasLoggedSet` and `nextPendingSet`.
- `SessionHeader` keeps its rest row for the whole workout once a set is logged. It switches between a resting state and a rested state of identical height.

No schema, storage or sync change.

**Tech Stack:** Flutter (fvm 3.44.0), provider/ChangeNotifier, flutter_test, ARB l10n (en/it/de/es).

**Spec:** `docs/superpowers/specs/2026-09-29-live-loop-stability-design.md`

## Review Focus

1. **Rest ran out while the app was in the background:** on return, the count-up must measure from when rest actually ended, not from the moment the app noticed. `SessionManager` calls `stopRest()` late. Test in Task 2 ("a late stopRest dates the end to when rest ran out").
2. **The ticker's 0-to-stop gap:** for up to a second after the countdown hits 0, `restStart` is still set and `restEndedAt` is still null. The header must already read `RESTED 0:0x` counting from the end, not a blank label. Test in Task 3 ("a finished countdown the controller hasn't stopped yet reads as rested from its end").
3. **Tapping the set whose RIR strip is open:** the strip must close, because the set becomes the live card, and no stale prompt may survive. Test in Task 2 ("focusing any set closes the strip, including its own").
4. **A clock that jumps back:** `restEndedAt` can end up in the future. The count-up must clamp to `0:00`, not show a negative time. Test in Task 3 ("a future end clamps to 0:00; a very long rest caps at 99:59").
5. **2.0× text in Italian at 320dp:** the widest labels (RIPOSATO, "+30s", "Salta") must keep both rest states the same height with no overflow. Test in Task 3 (height matrix).

    Future<int> strayPixels(WidgetTester tester, Key frame) async {
      final boundary = tester.renderObject<RenderRepaintBoundary>(find.byKey(frame));
      final image = (await tester.runAsync(() => boundary.toImage()))!;
      final bytes = (await tester.runAsync(() => image.toByteData()))!;
      var stray = 0;
      for (var y = 0; y < image.height; y++) {
        for (var x = 0; x < image.width; x++) {
          if (x >= 100 && x < 300) continue;
          final o = (y * image.width + x) * 4;
          if (bytes.getUint8(o) + bytes.getUint8(o + 1) + bytes.getUint8(o + 2) > 0) stray++;
        }
